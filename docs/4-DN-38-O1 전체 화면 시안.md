## 4. 사용 규칙

### 4.1 공통 레이아웃 (전역 chrome)

| 영역 | 채택 | 내용 |
|------|------|------|
| 헤더 (Header) | ○ | 서비스명, 사용자 이름, [로그아웃], 역할별 메뉴(`components/app-shell.tsx`). 로그인 전 화면(TYPE-01)은 `components/auth-shell.tsx`로 헤더 없음 |
| 사이드바 (Sidebar) | **미채택** | 메뉴가 3~5개라 헤더 메뉴로 충분하다 |
| 상단 탭 바 (Tab Bar) | **미채택** | — |
| 푸터 (Footer) | **미채택** | — |
| 브레드크럼 | **미채택** | 계층이 한 단계다 |

메뉴 노출: 일반 사용자는 예약 현황·회의실 예약·내 예약, 회의실 관리 담당자는 여기에 회의실 관리·전체 예약이 더해진다. 시안은 회의실 관리 담당자 사용자로 표시한다.

### 4.4 상태별 UI

**전역 상태 화면**

| 상태 | 처리 | 내용 |
|------|------|------|
| 에러 | **전역** | 전체 화면 대체 — 안내 문구 + [다시 시도] · [이전 화면] (`StateError`). 폼 화면은 아래 유형별 규칙 |
| 권한없음 | **전역** | 전체 화면 대체 — 접근 권한 안내 문구 + [이전 화면] (`StateForbidden`) |

**유형별**

| 유형 | 로딩 | 빈 목록 | 에러 | 권한없음 |
|------|------|---------|------|----------|
| TYPE-01 인증 폼형 | 해당 없음(제출 중 버튼 비활성은 5-IM-11) | 해당 없음 | 폼 상단 알림 배너 + 사유 | 해당 없음 |
| TYPE-02 현황 그리드형 | 제목 줄 + Skeleton 5행 | 중앙 안내 문구(등록된 회의실 없음) | 전역 규칙 따름 | 전역 규칙 따름 |
| TYPE-03 폼형 | (변경) 폼 영역 Skeleton | 해당 없음 | 상단 알림 배너 + 사유 | 전역 규칙 따름 |
| TYPE-04 목록형 | 테이블 영역 Skeleton 5행 | 점선 테두리 영역 + 안내 문구 | 전역 규칙 따름 | 전역 규칙 따름 |
| TYPE-05 검색 목록형 | 결과 영역 Skeleton 5행 | 점선 테두리 영역 + 안내 문구(기간 내 예약 없음) | 전역 규칙 따름 | 전역 규칙 따름 |

시안에서는 주소 뒤 `?state=loading|empty|error|forbidden`로 각 상태를 미리 볼 수 있다. 이 미리보기 장치는 5-IM-11에서 실제 상태 연결로 대체한다.

시안에서 만들지 않은 것(5-IM-11 이후): 예약 취소 확인 대화상자(문구는 `lib/messages.ts`에 있다), 저장·취소 성공 알림, 입력값 오류 표시.

### 5.3 리터럴 잔존 점검

| 금지 패턴(`4-DN-33-O1` §8.1) | 점검 수단 | 결과 |
|------|------|------|
| 토큰을 우회한 리터럴 값(HEX·픽셀) | `frontend/src`에서 `globals.css`를 제외하고 `#[0-9a-fA-F]{3,8}`, `\[\d+px\]`, `bg-(slate\|gray\|blue\|red\|green)-`, `style=` 검색 | 없음. 단 shadcn/ui 생성물 `components/ui/badge.tsx`에 `ring-[3px]`(포커스 링 두께) 1건이 있으며 스택 제공 컴포넌트라 그대로 둔다. 시안 코드의 `min-w-[40rem]`는 시간표 최소 폭(rem 단위)이다 |
| 화면마다 만든 로컬 상태 배지·알림 | 상태 배지는 `StatusBadge`, 알림은 `Alert`, 상태 화면은 `ScreenState`만 사용했는지 화면 전수 확인 | 없음 |
| 색만으로 상태를 구분 | 예약 상태는 색 + 「예약됨」「취소됨」 라벨, 시간표 셀은 색 + 「예약됨」「비어 있음」 라벨 | 없음 |

그 밖의 §8.3 자가 점검: 상태별 UI 구현(`ScreenState`) 확인, 라이트 테마만 사용, 화면에 요구사항·화면 ID 같은 내부 식별자를 그리지 않음. 360px 폭 가로 스크롤 없음은 코드 구조(고정 폭 없음, 현황은 목록으로 전환)로 확인했고 실기기 측정은 하지 않았다. 검증 명령(`npm run typecheck`, `lint`, `build`, `test`)은 모두 통과했고 전체 경로가 개발 서버에서 200으로 응답했다.

## 6. 발주처 컨펌 ① 기록

발주처(client)가 `부재`라 1인 프로젝트 규칙에 따라 PM이 남긴 `external_confirmed`(`kind: PM 대리`, `proxy_basis: 유형—부재`, `risk: RSK-01`) 한 건으로 갈음한다. `.nuriaim/approvals.yaml` 참조. 이 기록은 발주처의 실제 확인이 아니며, 설계 검수 조서(`4-DN-38-O2`)는 만들지 않는다(계약 설계 검수 요구 없음 — 킥오프 생략, 수행계획서 §6).
