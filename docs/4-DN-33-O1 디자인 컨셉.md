## 3. 시각적 방향

사내 직원이 업무 중 짬을 내어 회의실을 찾고 예약하는 업무 도구다. 장식보다 **한눈에 비어 있는 시간을 읽는 명료함**을 우선한다. 상태(예약됨·취소됨·내 예약)는 색만으로 구분하지 않고 라벨을 함께 둔다.

| 항목 | 값 |
|------|-----|

| 주 사용 환경 | 데스크톱 중심, 모바일 웹은 조회·예약·취소 최소 동작 |

## 8. 지켜야 할 규칙

### 8.1 금지 패턴

| 금지 | 대신 |
|------|------|
| 토큰을 우회한 리터럴 값 (HEX·픽셀 직접 지정) | 토큰 이름으로 참조 |
| 화면마다 만든 로컬 상태 배지·알림 | 공용 컴포넌트 |
| 색만으로 상태를 구분 | 색과 라벨을 함께 표시 |
| 관리 화면(`SCR-MTR-001`~`003`)에 모바일 전용 레이아웃 | 데스크톱 레이아웃만 (대상 밖) |

### 8.2 네이밍 규칙

| 대상 | 규칙 |
|------|------|
| 디자인 토큰 | shadcn/ui 관례의 CSS 변수(`--primary`, `--destructive`, `--background` 등) + 프로젝트 상태색은 `--success`, `--warning`, `--info` |
| 컴포넌트 | shadcn/ui의 공식 명칭을 따른다 (PascalCase) |

### 8.3 완료 기준

화면 하나를 「다 만들었다」고 할 때 무엇이 충족돼야 하는지 적는다. 전체 화면 시안 작성(`4-DN-38`)이 화면마다
이것으로 자가 점검하고, 전체 화면 코드베이스 통합(`5-IM-11`)이 배선 후 다시 본다.

- [ ] 토큰을 우회한 리터럴 값이 없다
- [ ] 상태별 UI(로딩·빈 목록·에러·권한없음)가 구현되어 있다 (`4-DN-36-O1` §2 전역 상태 메시지)
- [ ] §7 「지원 테마」에 명시된 라이트 테마에서 확인했다
- [ ] 모바일 대상 화면은 768px 미만·360px 폭에서 가로 스크롤 없이 동작한다
