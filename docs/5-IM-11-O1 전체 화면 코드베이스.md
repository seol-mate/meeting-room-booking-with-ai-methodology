| TYPE-01 인증 폼형 | 2 | 해당 없음 | 해당 없음 | ○ (폼 상단 알림) | 해당 없음 | 전체 화면 시안(`4-DN-38-O1`) §4.4와 같다 |

| TYPE-03 폼형 | 2 | ○ (회의실 목록·변경 대상 불러오는 중) | 해당 없음 (회의실이 하나도 없으면 안내만 표시) | ○ (폼 상단 알림) | ○ (SCR-MTR-002는 `RoleGuard`) | — |

- 시안 단계에 있던 `?state=` 미리보기 장치는 걷어냈다. 상태는 이제 실제 조회 결과(React Query)로 정해진다.
- 라우팅: 앱 라우터 하나로 일원화했고 `react-router` 의존성·런타임 코드가 없다(`package.json` 검색 0건).
- 공통 레이아웃(`4-DN-38-O1` §4.1): 「채택」인 헤더만 구현했다(`src/components/layout/app-header.tsx` — 서비스명, 역할별 메뉴, 사용자 이름, [로그아웃], 현재 메뉴 활성 표시). 사이드바·상단 탭 바·푸터·브레드크럼은 만들지 않았다.
- 통합 구성: 화면 → React Query 훅(`src/hooks`) → mock API(`src/mock/api.ts`) 순이다. API 결선(5-IM-14)에서는 mock API 함수 본문만 실제 호출로 바꾸고 `src/mock`을 걷어낸다. mock API는 API 명세서(`5-IM-12-O1`)의 operation과 같은 검증·권한·상태 코드 규칙을 따른다.
- 폼 검증은 Zod 스키마(`src/lib/schemas.ts`)로 하고 메시지는 `4-DN-36-O1`의 `message_key` 문구(`src/lib/messages.ts`)를 쓴다. 화면별 키는 모두 화면에서 쓰인다. 전역 키 `common.state.empty`·`saved`·`saveFailed`는 화면별 키가 있어 쓰지 않았다.
- 셀렉트박스: 회의실 선택은 회의실 목록 조회(mock `listRooms`), 시각 선택은 00:00~23:30 30분 단위 고정 목록으로 `4-DN-36-O1` §4 명세와 같다.
- 시각 검수·초기 설정 감사 중 고친 것: 모바일 [예약] 버튼 하단 고정, 내 예약 모바일 카드 목록, 시간표 열 너비 균등화, 대화상자 닫기 버튼 중복 제거(`showCloseButton={false}`).
