## 4. UAT 시나리오

### 4.1 시나리오 목록 및 사전 합의 (실행 전에 채운다)

> 시나리오는 업무 흐름(`PROC-ID`) 단위이고, 확인 항목(기대 결과)은 사용자 스토리(`3-AN-08-O2`) 수용 기준에서 가져왔다. 시나리오 목록 버전: **§4.1 v0.1 (8건)**.
> 시스템 테스트(`6-TS-13`)가 같은 수용 기준 17개와 예외 흐름 17개를 이미 실행했다 — 아래는 사용자가 업무로 한 번 더 확인하는 대표 흐름이다.
> `6-TS-01-O1` §5.6 「UAT 확인 항목」에 이관된 항목은 없다(`— (해당 없음)`).

| 시나리오 ID | 시나리오명 | 근거 (PROC-ID / REQ-ID / US-ID) | 확인 항목 (기대 결과) |
|------------|----------|--------------------------------|----------------------|
| UAT-001 | 직원이 계정을 만들어 로그인하고, 로그인하지 않으면 쓸 수 없다 | PROC-RSV-01 / REQ-F-001, REQ-NF-001 / US-08 | 가입한 계정으로 로그인하면 예약 기능을 사용할 수 있다(US-08.1). 로그인하지 않은 사용자의 모든 기능 요청은 거부된다(US-08.2). 잘못된 비밀번호로는 로그인되지 않는다 |
| UAT-002 | 빈 회의실을 찾아 예약한다 | PROC-RSV-02, PROC-RSV-03 / REQ-F-002, REQ-F-003 / US-01, US-02 | 날짜를 선택하면 회의실별 시간대 예약 여부와 예약자가 표시된다(US-01.1). 회의실·시작·종료 시각을 선택해 예약하면 예약이 등록되고 예약 현황에 반영된다(US-02.1) |
| UAT-003 | 다른 직원의 회의 제목은 보이지 않는다 | PROC-RSV-02 / REQ-F-002 / US-01 | 회의 제목은 예약자와 회의실 관리 담당자에게만 표시되고 다른 직원에게는 표시되지 않는다(US-01.2) |
| UAT-004 | 잘못된 시간·겹치는 시간으로는 예약되지 않는다 | PROC-RSV-03 / REQ-F-003, REQ-F-004 / US-02, US-03 | 30분 단위가 아니거나 30분 미만 또는 4시간 초과이면 예약이 거부된다(US-02.2). 기존 예약과 일부라도 겹치면 거부되고 "이미 예약됨"이 안내된다(US-03.1). 거부된 요청은 기존 예약을 바꾸지 않는다(US-03.2) |
| UAT-005 | 내 예약을 취소하고 이력을 확인한다 | PROC-RSV-04 / REQ-F-005 / US-04 | 시작 전 본인이 취소하면 예약이 해제되고 그 시간이 예약 가능으로 표시된다(US-04.1). 시작 이후에는 취소가 거부된다(US-04.2). 취소한 예약의 이력이 조회된다(US-04.3) |
| UAT-006 | 관리 담당자가 다른 사람의 예약을 취소한다 | PROC-RSV-04 / REQ-F-006 / US-05 | 관리 담당자는 시작 전의 다른 사람 예약을 취소할 수 있다(US-05.1). 관리 담당자가 아닌 사용자가 다른 사람의 예약을 취소하려 하면 거부된다(US-05.2) |
| UAT-007 | 관리 담당자가 회의실을 등록하고 변경한다 | PROC-MTR-01 / REQ-F-007 / US-06 | 회의실명·위치·수용 인원·비치 장비를 입력해 등록할 수 있다(US-06.1). 변경한 정보가 예약 화면에 반영된다(US-06.2). 관리 담당자가 아닌 사용자는 등록·변경할 수 없다(US-06.3) |
| UAT-008 | 관리 담당자가 기간별 전체 예약을 조회한다 | PROC-MTR-02 / REQ-F-008 / US-07 | 회의실과 기간을 지정하면 해당 기간의 예약(시간·예약자·회의 제목)이 목록으로 표시된다(US-07.1). 취소된 예약은 목록에서 제외되고 취소 이력에서 확인된다(US-07.2) |

**합의 기록**

아직 남기지 않았다. 실행 전에 PM이 `.nuriaim/approvals.yaml`에 시나리오 합의 `external_confirmed`(`seen: §4.1 v0.1 (8건)`, `kind: PM 대리`, `proxy_basis: 유형—부재`, `result: 확인`)를 남기고, 그 `at`이 UAT 시작일보다 앞서야 한다. 실행 중 시나리오를 바꾸면 이 목록의 버전을 올려 다시 남긴다.

**실행 준비** (환경 지원 — QA)

1. DB·Backend·Frontend를 띄운다: README 「개발환경」의 기동 방법(`docker compose up -d --wait` → `SPRING_PROFILES_ACTIVE=local ./mvnw spring-boot:run` → `npm run dev`, http://localhost:3000).
2. 일반 직원 계정 2개는 가입 화면(`/join`)에서 만든다. 회의실 관리 담당자 계정은 가입한 뒤 DB에서 올린다(생성 수단 미정 — 조건 C2): `update reserver set role='ROOM_MANAGER' where login_id='<ID>'`. 시스템 테스트에서 만든 `uat-staff1`/`uat-staff2`(비밀번호 `pw-12345`)와 관리 담당자 `e2eprobe`(비밀번호 `x`)를 그대로 써도 된다.
3. 로그아웃 기능이 없어(5-IM-22 기각) 계정을 바꾸려면 다른 브라우저 창(시크릿 창)을 쓴다.
