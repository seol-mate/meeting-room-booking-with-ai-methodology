### 3.1 요구사항 커버리지

> 대상 REQ-ID는 두 도메인 API 명세서의 `x-req-ids` 합집합(REQ-F-001 ~ REQ-F-008)이다. REQ-NF-001은 `x-nf-req-ids`에만 있어 분모가 아니며 IT-001·IT-004·IT-006이 보인다(미로그인 401).

| REQ-ID | 요구사항 | 검증 시나리오 | 결과 |
|--------|---------|--------------|------|
| REQ-F-001 | 직원은 계정을 만들어 로그인할 수 있어야 한다 | IT-001, IT-002 | Pass |
| REQ-F-002 | 로그인한 직원은 회의실별·일시별 예약 현황을 조회할 수 있어야 한다 | IT-004, IT-015 | Pass |
| REQ-F-003 | 예약자는 회의실과 시작·종료 시각을 선택해 예약할 수 있어야 한다 | IT-004, IT-007, IT-008, IT-013 | Pass |
| REQ-F-004 | 이미 예약된 시간과 겹치는 예약은 거부되어야 한다 | IT-004, IT-009, IT-010, IT-013, IT-017 | Pass |
| REQ-F-005 | 예약자는 시작 전에 자신의 예약을 취소할 수 있어야 하고 취소 이력이 남아야 한다 | IT-011, IT-012 | Pass |
| REQ-F-006 | 회의실 관리 담당자는 시작 전의 다른 사람 예약을 취소할 수 있어야 한다 | IT-006, IT-014, IT-016 | Pass |
| REQ-F-007 | 회의실 관리 담당자는 회의실을 등록하고 변경할 수 있어야 한다 | IT-003 | Pass |
| REQ-F-008 | 회의실 관리 담당자는 회의실과 기간별로 전체 예약 내용을 조회할 수 있어야 한다 | IT-005 | Pass |

> 검증 시나리오가 없는 REQ는 없다. 위임 행도 없다.

### 3.3 계층 커버리지

> 단위 테스트(`6-TS-11`)가 판정하지 않고 넘긴 `presentation`·`persistence` 계층을 여기서 판정한다(라인 커버리지 80%). 통합 테스트(`-Pintegration`) 17건만으로 잰 값이다.

## 5. 결론

- 17건 전체 Pass, 발견한 결함 없음. `presentation` 82.2%로 80% 이상, `persistence`는 질의 메서드 9개 전부 실제 DB에서 실행·단언
