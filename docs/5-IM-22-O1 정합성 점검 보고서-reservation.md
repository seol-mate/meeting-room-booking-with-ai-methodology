## 6. 다음 활동으로 가져가도 되는 가정

- 로그인 ID 중복(409)과 이미 취소된 예약의 재취소(422)는 업무프로세스 정의서에 예외 흐름이 없다 — 업무프로세스 정의서(`3-AN-09-O1`) 개정으로 EX를 소급 발급할 대상이다(초안의 `— (소급 예정: …)` 2건).
- 도메인 분석표(`3-AN-05-O1`)의 BR-01~03 「미정」 표기와 `TO-BE(미확정)` 상태는 확정된 요구사항으로 이미 해소되어 있다. 정정으로 최신화를 권고하고, 30분 단위·최소 30분·최대 4시간 규칙(REQ-F-003)은 업무 규칙(BR)으로 올라 있지 않다.
- 비밀번호 해시는 BCrypt(`spring-security-crypto` 의존성 추가)로 한다.
- 최초 `ROOM_MANAGER` 계정을 만드는 방법이 없다(조건 C2 미결). 지정 방식이 정해질 때까지 DB의 `reserver.role`을 직접 바꾼다.
- 예약 가능 시간대·과거 시각 예약 제한은 서버가 두지 않는다(조건 C3 미결).
- 로그아웃 operation 기각(§5 #1)에 따라 서버에는 로그아웃이 없다. 세션은 만료(조건 C3 미결, 임시 30분)로만 끝난다. 공통 헤더의 [로그아웃](C-CMN-06, Should)은 Frontend 코드 구현(`5-IM-14`)에서 제거하거나 화면에서만 처리하도록 정하고, UI&UX 제약사항의 조건 C4(로그아웃 요구사항 부재)는 「요구하지 않음」으로 닫는다.
