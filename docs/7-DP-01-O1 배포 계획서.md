## 2. 배포 개요

| 항목 | 내용 |
|------|------|
| 배포 방식 | In-Place (단일 서버의 컨테이너를 새 버전으로 교체) + 배포 전 상태 보존 |
| 배포 대상 | 이 개발 PC(Windows 11)의 Docker — `web`(Next.js) · `api`(Spring Boot) · `db`(PostgreSQL 17) 컨테이너 3개를 한 compose 프로젝트로 기동한다 (시스템 아키텍처 정의서 `4-DN-01-O1` ADR-06). 운영 서버 유형은 「개인 PC의 Docker」로 확정한다. Dockerfile·운영용 compose·포트·환경 변수는 운영 환경 구성(`7-DP-02`)에서 만든다 |
| 배포 윈도우 | 제한 없음 — 이용자가 없는 개인 프로젝트라 점검 시간을 두지 않는다. 배포일·시각은 실행하는 날 PM이 정하고 §8에 적는다 |
| 데이터 이행 여부 | 생략 |
| 이행 생략 사유 | 신규 구축이라 AS-IS 데이터가 없다(WBS `7-DP-03` 해당 없음). 운영 DB는 빈 상태에서 Flyway V1 마이그레이션(`V1__create_initial_tables.sql`)으로 스키마만 만든다 |
| 배포 위험 | `RSK-13` (CI/CD 없음 — 배포를 사람이 순서대로 실행) · `RSK-14` (테스트 환경과 운영 환경 차이 — 재점검 주기 `7-DP-01 착수 전`, 아래 재판정) · `RSK-15` (UAT 생략, 인수 확인 없음) · `RSK-06` (1인 팀 자체 승인) |

**RSK-14 재판정 (7-DP-01 착수 전)**: 이 계획으로 운영과 테스트가 같은 개발 PC·같은 Docker 위에 놓이므로 「운영 서버 사양·OS가 다르다」는 차이가 사라진다. 남는 차이는 테스트에서는 Testcontainers의 일회용 DB, 운영에서는 영속 볼륨 DB를 쓴다는 점뿐이며, Flyway가 같은 마이그레이션(V1)을 적용하므로 위험을 낮음으로 본다. 상태는 `미종결` 유지(운영 compose 구성 후 7-DP-04 Smoke로 최종 확인).

## 4. 체크리스트 (배포 전 · 중 · 후)

### 4.1 배포 전 (사전 준비)

- [ ] 배포할 커밋 확인(`git status` 깨끗, 릴리즈 태그 후보 `v1.0.0`) — 단위·통합 테스트(`./mvnw test`, `npm test`)와 `npm run build` 통과
- [ ] 배포 패키지(이미지) 빌드 및 이미지 ID·SHA256 기록
- [ ] 배포 전 상태 보존: 운영 DB `pg_dump` 백업 파일과 직전 이미지 태그 보존 (첫 배포는 빈 DB·이전 이미지 없음을 기록)
- [ ] 운영용 `.env`(DB 비밀번호 등) 준비 — 저장소에 올리지 않음
- [ ] 포트 충돌 확인 (이 PC는 8080=Jenkins, 5432=로컬 PostgreSQL이 이미 사용 중 — 운영 포트는 `7-DP-02`에서 확정)

### 4.2 배포 중

- [ ] 기존 운영 컨테이너 정지(최초 배포는 해당 없음)
- [ ] 운영 compose 기동 → `db` 헬스 통과 → `api` 기동(Flyway 적용 로그 확인) → `web` 기동
- [ ] 신규 버전 헬스체크 통과 (`/actuator/health` UP)
- [ ] Smoke Test 실행 결과 정상 — 가입 → 로그인 → (관리 담당자) 회의실 등록 → 예약 → 취소 → 로그인 없는 접근 401 (롤백 판정 시점: Smoke 종료 직후)
- [ ] 오류율·응답시간 모니터링 시작 (§6 측정 수단)

### 4.3 배포 후

- [ ] 배포 검증 체크리스트(`7-DP-04-O1`) 전 항목 통과
- [ ] 30분간 오류율 기준 이내 유지 확인
- [ ] 직전 이미지·백업 보존 기간 명시 (아래 §6 최소 24시간)
- [ ] Smoke 데이터 정리 — 삭제 명령: `delete from reservation where meeting_room_id in (select meeting_room_id from meeting_room where name like 'SMOKE %'); delete from meeting_room where name like 'SMOKE %'; delete from reserver where login_id like 'smoke-%';` 확인: 같은 조건의 `select count(*)`가 0 / 담당: 설동혁
- [ ] 배포 완료 공지(자기 기록) 및 운영 인수인계(`8-OP-01`)
- [ ] 릴리즈 버전 태그 `v1.0.0`(규약은 VCS 운영전략 `9-CM-03`) 기록 — 사람이 수행한다. 배포 이력은 `7-DP-04-O1`이 정본이다

## 5. 배포 타임라인

> 윈도우 제한이 없어 절대 시각 대신 시작 시점(T)에서의 경과 시간으로 적는다. 배포일·시각은 실행하는 날 §8에 적는다.

| 시각 | 작업 | 담당 |
|------|------|------|
| T+0 | 배포 전 체크리스트(§4.1) 확인, 이미지 빌드, DB 백업 | 설동혁 |
| T+20분 | 운영 compose 기동, Flyway 적용 확인 | 설동혁 |
| T+30분 | 헬스체크 통과 확인 후 Smoke Test | 설동혁 |

| T+75분 | 30분 모니터링 종료, 배포 후 체크리스트(§4.3) 정리 | 설동혁 |

## 6. 롤백 계획

| 항목 | 내용 |
|------|------|
| 롤백 트리거 (Block) | 배포 후 5분 내 5xx 오류율 **1%** 초과 (요청이 100건 미만이면 5xx 3건 이상) · Smoke Test 핵심 기능(가입·로그인·예약 등록·취소) Fail · `/actuator/health`가 UP이 아님 · DB 접속 불가 |
| 오류율 측정 수단 | api 요청 로그 집계: 5xx 건수 `docker compose logs --since 5m api \| grep -cE ' -> 5[0-9]{2} '`, 전체 건수 `docker compose logs --since 5m api \| grep -cE ' -> [0-9]{3} '` (요청 로그 형식 `METHOD PATH -> 상태 (ms)`) — 운영 환경 구성 체크리스트(`7-DP-02-O1`) §7은 알림 연결 확인만 한다 |
| 조건부 판정 구간 | 오픈 후 30분 오류율 **0.1% 초과 1% 이하** — PL이 원인 확인 후 판정 (`7-DP-04-O1` §6) |
| Pass 기준 | 오픈 후 30분 오류율 **0.1% 이하** |
| 앱 롤백 방식 | 새 컨테이너를 내리고 보존해 둔 직전 이미지 태그로 compose를 다시 기동한다 (소요 약 5분). 첫 배포는 되돌릴 이전 버전이 없어 컨테이너를 내리는 것이 롤백이다 |
| **스키마·데이터 변경 포함** | 있음 — 첫 배포의 Flyway V1(`V1__create_initial_tables.sql` — 초기 테이블과 예약 겹침 배제 제약). 빈 DB에 새로 만드는 변경이라 DB 롤백 방식은 **볼륨 삭제 후 재생성**(되돌릴 운영 데이터 없음). 이후 릴리즈의 스키마 변경은 전방 수정(새 마이그레이션) 또는 `pg_dump` 복원으로 되돌린다 — 그때 이 행을 개정한다 |
| 데이터 롤백 방식 | 해당 없음 — 데이터 이행이 없다. 운영 사용 시작 뒤에는 배포 전 `pg_dump` 복원(소요: 데이터 규모에 따라 수 분) |
| **Point of no return** | 첫 사용자가 운영 DB에 데이터를 쓴 시점. 그 뒤에는 백업 복원이 그 이후 데이터를 잃으므로 앱만 되돌리고 데이터는 결함 관리(`8-OP-03`) 수정 → 재배포(`7-DP-04`)로 처리한다 |
| 롤백 담당자 | 설동혁 (PL·TA·DV) |
| 직전 환경 보존 기간 | 직전 이미지 태그와 `pg_dump` 파일을 배포 후 최소 24시간 보존 |
| 배포 전 상태 보존 (초회 In-Place 배포 — 구 버전 환경 없음) | 첫 배포: 이전 상태 없음(빈 DB) — 배포 직전 `pg_dump`(빈 스키마)와 빌드한 이미지 ID를 `docs/evidence/7-DP/`에 기록. 이후 릴리즈: 직전 이미지 태그 + 배포 직전 `pg_dump` 파일 위치와 보존 기간을 해당 버전 행에 기록 |
| 롤백 뒤 경로 | 원인을 결함 관리(`8-OP-03`) `BUG-NNN`으로 등록 → 수정 → 이 계획서 버전 상향·PM 재승인 → 배포 실행 및 검증(`7-DP-04`) 재수행 |
