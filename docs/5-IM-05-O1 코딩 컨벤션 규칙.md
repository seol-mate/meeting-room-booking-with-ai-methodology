# 5-IM-05-O1 코딩 컨벤션 규칙

> 모든 구현 단계(FE·BE)의 Agent Prompt에 공통 입력으로 들어가는 문서다. 공통 개발규칙(`4-DN-21-O3`)에 이미 정의된 것은 여기 옮겨 적지 않고 참조한다(Hierarchical Specification). 하류(`5-IM-11`·`13`·`14`·`24`, 시스템 테스트(`6-TS-13`)·E2E 자동화 테스트(`6-TS-15`))가 절 번호로 이 문서를 인용하므로 절 구성을 바꾸지 않는다.

## 2. 명명 규칙

공통 개발규칙(`4-DN-21-O3`) §6 `none` 절 「네이밍 규칙」(Java 표준·접미어·snake_case·테이블 접두어 없음)이 기본이다. 아래는 그 위에 이 프로젝트가 구체화한 것만 적는다.

| 대상 | 규칙 | 예 |
|------|------|-----|
| 클래스 | PascalCase, 접미어 `XxxController`·`XxxService`·`XxxRepository`·`XxxEntity`·`XxxRequest`/`XxxResponse` | `ReservationService` |
| 엔티티 클래스 | 엔티티 명세서(`entities.yaml`)의 `name` + `Entity`. 명세의 엔티티 이름과 1:1로 찾을 수 있게 한다 | `MeetingRoom` → `MeetingRoomEntity` |
| 열거형(코드) | 코드 정의서(`4-DN-21-O2`)의 코드 그룹 이름을 PascalCase로, 값은 코드 정의서의 값 그대로(UPPER_SNAKE) | `ReservationStatus.RESERVED` |
| 메서드 | camelCase 동사구. 조회 `find…`·`get…`, 등록 `create…`, 변경 `update…`, 취소·삭제 `cancel…`·`delete…` | `findByMeetingRoomId`, `cancel` |
| 변수·필드 | camelCase. 불리언은 `is`/`has` 접두어 없이 형용사 | `started`, `active` |
| 상수 | UPPER_SNAKE | `MAX_PAGE_SIZE` |
| 파일명 (BE) | 클래스명과 같게 | `ReservationService.java` |
| 테스트 클래스·메서드 (BE) | 클래스 `XxxTest`(통합은 `XxxIntegrationTest`), 메서드 `대상_조건_기대결과` | `ReservationServiceTest.create_withOverlap_throwsConflict` |
| 마이그레이션 파일 | `V{번호}__{snake_case 설명}.sql`. 이미 적용된 파일은 수정하지 않는다 | `V1__create_meeting_room.sql` |
| DB 이름 | snake_case, 테이블 접두어 없음(`entities.yaml`의 `table`·`column`과 일치). 제약·인덱스 이름은 ERD(`4-DN-14-O2`) 각 문서의 제약 표에 적힌 이름을 그대로 쓴다 | `meeting_room`, `start_at` |
| 파일명 (FE) | 컴포넌트·훅·유틸 모두 kebab-case 파일. 내보내는 컴포넌트는 PascalCase, 훅은 `useXxx` | `status-badge.tsx` → `StatusBadge`, `use-reservations.ts` |
| 테스트 파일 (FE) | 대상 파일 옆에 `대상.test.ts(x)` | `app-store.test.ts` |
| 봉투 생성 방식 | `EnvelopeFactory` DI 빈 — 봉투에 요청 ID(`requestId`)를 채워야 해서 정적 팩토리를 쓰지 않는다(`4-DN-21-O3` §2) | `envelopeFactory.ok(data)` |

## 3. 패키지 구조 규칙

```text
com.example.meetingroom          (루트 접두는 임시 — 수행 조직 확정 시 변경)
├─ domain.reservation/    controller · service · repository · entity · dto   (예약자 계정 포함)
├─ domain.meetingroom/    controller · service · repository · entity · dto
└─ common/                config · exception · util · envelope
```

- 도메인 우선·레이어 하위 구조. 도메인 간 호출은 Service 레이어에서만(`4-DN-21-O3` Service 규칙). 다른 도메인의 Repository·Entity를 직접 다루지 않는다.
- `common`은 도메인을 알지 못한다 — `domain.*`을 import하지 않는다. `envelope`에는 `Envelope`·`ValidationError`·`EnvelopeFactory`를 둔다(`4-DN-21-O3` §2의 스키마 이름).
- 테스트는 `src/test/java`에 같은 패키지 구조로 둔다.
- 마이그레이션은 `backend/src/main/resources/db/migration`에 둔다.
- **FE**: §2가 기본값(Next.js App Router)이다.
  - **화면 폴더 규칙(프로젝트 값)**: 로그인 전 화면은 `src/app/(auth)/<기능>/page.tsx`, 로그인 후 화면은 `src/app/(app)/<기능>/page.tsx`, 회의실 관리 담당자 전용 화면은 `src/app/(app)/admin/<기능>/page.tsx`. 도메인 폴더를 한 단계 더 두지 않는다(화면이 8개뿐이고 사이트맵의 메뉴 구조가 곧 폴더 구조다).
  - 공용 UI는 `src/components/ui/`(shadcn/ui 프리미티브), 프로젝트 공용 컴포넌트는 `src/components/`, 훅은 `src/hooks/`, 전역 상태는 `src/store/`, HTTP·스키마·유틸은 `src/lib/`, 사용자 메시지 문구는 `src/lib/messages.ts`.
  - **API 계약 타입 위치(프로젝트 값)**: API 명세서(`5-IM-12`)에서 생성한 타입은 `src/types/api-<도메인 ID>.d.ts`(`npm run codegen:api`가 생성). 생성물이므로 손으로 고치지 않는다.
  - 시안 표시용 고정 데이터는 `src/mock/`에 있고 Frontend 코드 구현(`5-IM-14`)에서 API 결선 때 걷어낸다(`4-DN-38-O1` §1).

## 4. 주석 규칙

- 공개 API(Controller 메서드·공용 유틸)에는 한 줄 요약 주석. 자명한 getter·setter에는 붙이지 않는다.
- 주석은 「왜」를 적는다. 코드를 그대로 되풀이하는 주석은 쓰지 않는다. 언어는 한국어.
- **테스트 추적 주석 `@trace`** — 형식의 정본은 코딩 컨벤션 규칙 작성(`5-IM-05`) 「테스트 추적 주석 규칙」이며 바꾸지 않는다. 테스트 메서드·케이스 바로 위 한 줄, 형식 `@trace {REQ-ID 목록} | {단계 근거 ID}`. 근거 요구사항이 없는 공통·기반 기능 테스트는 `@trace —`와 사유. `operationId`가 없는 `TE-ID`는 `@trace {REQ-ID 목록} | {TE-ID}`로 근거 ID 자리에 `TE-ID`만 적는다. 구현 코드에는 붙이지 않는다. 아래 예시의 ID는 형식을 보이기 위한 것이며, 실제 테스트에는 상류 산출물에 있는 ID를 쓴다.

```java
// @trace REQ-F-004 | TE-reservation-U02, createReservation
@Test
void create_withOverlap_throwsConflict() { ... }
```

```typescript
// @trace REQ-F-003 | SCR-RSV-004 V-SCR-RSV-004-01
it('시작 시각이 종료 시각보다 늦으면 오류를 표시한다', () => { ... })
```

```java
// @trace — | PGM-CMM-001 (공통 기능 — 근거 요구사항 없음, 응답 봉투 생성 빈)
@Test
void ok_withData_fillsRequestId() { ... }
```

```java
// @trace — | skeleton (5-IM-01 스캐폴딩 골격 테스트 — 6-TS-11 분모 제외, im-01.P14)
@Test
void contextLoads() { ... }
```

## 5. 금지 패턴

| 금지 | 대신 | 근거 |
|------|------|------|
| Controller 안의 비즈니스 로직 | Service로 이동. Controller는 `@Valid` 검증과 봉투 변환만 | 공통 개발규칙(`4-DN-21-O3`) Controller 규칙 |
| Repository 안의 업무 판단 | Service에서 판단, Repository는 조회·저장만 | `4-DN-21-O3` Repository 규칙 |
| 엔티티를 API 응답으로 직접 직렬화 | `XxxResponse` DTO로 변환(목록은 프로젝션 DTO 직접 반환) | `4-DN-21-O3` Controller·Repository 규칙 |
| `ddl-auto`를 `validate` 외 값으로 변경, 스키마를 코드·콘솔로 직접 변경 | 스키마 변경은 Flyway 마이그레이션 파일 추가로만 | ERD-overview(`4-DN-14-O1`) §1 |
| 적용된 마이그레이션 파일 수정 | 새 버전 파일 추가 | Flyway 체크섬 검증 |
| `System.out`·`printStackTrace()` | SLF4J 로거. 형식은 `4-DN-21-O3` §5 | 로깅 규칙 |
| 비밀번호·비밀번호 해시·접속 정보를 로그에 기록하거나 코드·저장소에 하드코딩 | 환경 변수(`.env.example` 참고)로 주입 | `4-DN-21-O3` §5, 개발환경 README |
| 빈 `catch` 블록(예외 삼키기) | 로깅 후 재던지거나 `GlobalExceptionHandler`에 위임 | `4-DN-21-O3` §4 |
| 화면 컴포넌트에서 `axios`를 직접 import해 호출 | `src/lib/axios.ts` 인스턴스를 쓰는 API 모듈·React Query 훅 경유 | 개발환경 세팅(`5-IM-01`) HTTP 클라이언트 |
| TypeScript `any`, 생성된 API 타입(`src/types/api-*.d.ts`) 수기 수정 | 타입 정의 또는 `unknown` + Zod 검증, 명세서를 고친 뒤 재생성 | 스키마 검증 역량 |
| 토큰을 우회한 리터럴 값(HEX·px), 팔레트 유틸(`bg-slate-*` 등) 직접 사용 | 디자인 토큰 이름 참조 | 디자인 컨셉(`4-DN-33-O1`) §8.1 |
| 새 코드에서 시안 데이터(`src/mock`) 참조 | API 결선된 훅 사용 | 전체 화면 시안(`4-DN-38-O1`) §1 |

**EOL·인코딩**: 줄바꿈은 LF로 통일하고 저장소 루트에 `.gitattributes`(`* text=auto eol=lf`)를 둔다. 파일 인코딩은 UTF-8(BOM 없음). CRLF/LF 혼재는 재작성 파일의 diff를 전문 재작성으로 보이게 한다.
