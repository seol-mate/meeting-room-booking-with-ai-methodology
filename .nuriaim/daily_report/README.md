# 일간 작업 기록 지침

프로젝트 작업자가 업무를 마칠 때 그날 한 일을 한 파일로 남긴다. 사람과 에이전트가 함께 따르는 지침이다.

> 프로젝트를 처음 세팅할 때 이 파일이 프로젝트의 `.nuriaim/daily_report/README.md`로 복사된다. 방법론의 정식
> 산출물이 아니므로 품질 게이트·승인 대상이 아니며, 프로젝트에 맞게 고쳐 써도 된다.

## 언제

업무를 마칠 때 작업자가 「오늘 업무 마감」(또는 「일간 작업 기록 작성」)이라고 요청하면 에이전트가 이 지침대로 기록한다.
하루에 한 번이 원칙이다. 같은 날 다시 요청하면 그날 파일을 고쳐 쓴다(새 파일을 만들지 않는다).

## 파일 위치와 이름

```
.nuriaim/daily_report/YYYY-MM/YYYY-MM-DD_<계정ID>.md
예) .nuriaim/daily_report/2026-10/2026-10-02_A12345.md
```

- `<계정ID>`는 사내 GitLab 계정 ID다(MCP 로그인 계정). 한글 이름은 파일 이름에 쓰지 않고 파일 안에 적는다 —
  한글 파일 이름은 도구·운영체제에 따라 깨질 수 있다.
- 계정 ID를 모르면 작업자에게 묻는다.
- 월 폴더(`YYYY-MM`)가 없으면 만든다.

## 기록 순서 (에이전트)

1. **작업자 확인** — `.nuriaim/session.yaml`의 `actor`(이름)와 git 사용자 이름으로 작업자를 정한다.
2. **자동으로 채울 것을 모은다** — 작업자에게 묻지 않고 기록에서 가져온다.
   - 오늘 이 작업자의 git 커밋 (`git log --since=<오늘 00:00> --author=<git 사용자 이름>`)
   - `.nuriaim/approvals.yaml`에서 오늘 날짜(`at`)이고 `by`가 이 작업자인 기록
   - 플랫폼 요청함(`check_messages`)의 오늘 보낸 요청·받은 요청·응답
3. **작업자에게 묻는다** — 막힌 점, 내일 할 일, 그 밖에 남길 메모. 없다고 하면 「없음」으로 적는다.
4. **아래 파일 구성대로 쓴다.** 산출물·활동은 「이름(번호)」로 적는다(예: 프로젝트 개요서(`1-PN-01-O1`) 0.2 버전).
5. **그 파일만 커밋한다** — 메시지는 `chore(daily): YYYY-MM-DD <계정ID>`. 다른 변경을 함께 담지 않는다.
   push는 작업자가 요청할 때 한다.

## 파일 구성

```markdown
# 일간 작업 기록 — YYYY-MM-DD

| 항목 | 내용 |
|---|---|
| 작업자 | 이름 (계정ID) |
| 역할 | session.yaml의 role |

## 1. 오늘 한 일

| 활동 | 산출물·버전 | 커밋 |
|---|---|---|
| 프로젝트 개요서 작성(1-PN-01) | 프로젝트 개요서(1-PN-01-O1) 0.2 버전 초안 | abc1234 |

## 2. 승인·확정·발주처 확인

- (approvals.yaml의 오늘 기록 — 없으면 「없음」)

## 3. 요청

- 보낸 요청: (없으면 「없음」)
- 받은 요청·응답: (없으면 「없음」)

## 4. 막힌 점

- (작업자 답변)

## 5. 내일 할 일

- (작업자 답변)

## 6. 메모

- (작업자 답변, 없으면 「없음」)
```

## 적지 않는 것

- 개인 평가에 쓰일 만한 내용(근무 시간·성과 평가·다른 사람에 대한 평가)
- 토큰·비밀번호 같은 비밀값
- 이 기록은 저장소 멤버 모두와 플랫폼 공용 열람 계정이 읽을 수 있다
